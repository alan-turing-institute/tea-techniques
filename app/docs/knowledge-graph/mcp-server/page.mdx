<Callout variant="info" title="What is MCP?">
  The [Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) is an open standard that lets AI assistants like Claude
  connect to external data sources. The TEA Techniques MCP server gives Claude direct access
  to our knowledge graph—enabling conversational discovery of all TEA techniques.
</Callout>

## Why Use the MCP Server?

Instead of manually browsing pages or writing API queries, you can ask an AI agent questions in natural language:

| Task | Manual Approach | With MCP |
|------|-----------------|----------|
| Find fairness techniques for neural networks | Browse categories, filter manually, read each page | *"Find fairness techniques that work with neural networks"* |
| Compare SHAP vs LIME | Open two tabs, compare side by side | *"Compare SHAP and LIME and help me evaluate which is the best one for my use case"* |
| Find evidence for an assurance claim | Search docs, map techniques to claims | *"What techniques support the claim that our model treats all groups fairly?"* |
| Explore related techniques | Follow links manually | *"What techniques are related to SHAP?"* |

## How It Works

<ThemedDiagram name="mcp-architecture" alt="Architecture diagram showing Claude connected to MCP Server which fetches from the Knowledge Graph" />

The MCP server runs locally on your machine and provides 10 tools that Claude can call. When you ask a question, Claude selects the appropriate tools, the server queries the knowledge graph, and Claude synthesises the results into a helpful response.

## Quick Start

No installation needed — run directly with `npx`:

```bash
npx @chrisdburr/tea-techniques-mcp
```

<Callout variant="info" title="First-use setup">
  On first run, the server fetches the knowledge graph and its precomputed vectors from GitHub Pages and caches them locally for 24 hours.
  Semantic search also downloads the MiniLM-L12 embedding model (about 130 MB) from Hugging Face the first time you
  ask for techniques for a claim. The model needs the package's optional dependencies (`@huggingface/transformers` and
  `onnxruntime-node`, installed by default); without them, or if the download fails, the server falls back to keyword search.
</Callout>

<details>
<summary>Local development (from source)</summary>


## Tool Reference

### Discovery Tools

Tools for finding and exploring techniques.

#### find_techniques

<Badge variant="secondary">Primary Search</Badge>

Search and filter techniques by query text, assurance goals, and tags.

| Parameter | Type | Description |
|-----------|------|-------------|
| `query` | string | Free-text search across names and descriptions |
| `goals` | string[] | Filter by goal slugs (e.g. `["explainability", "fairness"]`) |
| `tags` | string[] | Filter by tag fragments (e.g. `["model-agnostic", "tabular"]`) |
| `limit` | number | Max results (default 20) |

---

#### get_technique

<Badge variant="secondary">Detail View</Badge>

Get full details of a technique: goals, tags, use cases, limitations, related techniques, and resources.

| Parameter | Type | Description |
|-----------|------|-------------|
| `slug` | string | Technique slug (e.g. `shapley-additive-explanations`) |

---

#### compare_techniques

<Badge variant="secondary">Side-by-Side</Badge>

Compare 2-5 techniques across goals, tags, and resources.

| Parameter | Type | Description |
|-----------|------|-------------|
| `slugs` | string[] | Array of 2-5 technique slugs |

---

#### find_related

<Badge variant="secondary">Exploration</Badge>

Find techniques related via explicit links, shared goals, or shared tags.

| Parameter | Type | Description |
|-----------|------|-------------|
| `slug` | string | Technique slug to find relatives for |
| `depth` | number | 1 = explicit + same-goal, 2 = also same-tag (default 1) |

---

### Platform Integration Tools

Tools for connecting techniques to assurance arguments.

#### suggest_techniques_for_claim

<Badge variant="secondary">Claim Matching</Badge>

Given an assurance claim, suggest relevant techniques using embedding-based semantic search with hybrid RRF ranking.

| Parameter | Type | Description |
|-----------|------|-------------|
| `claim` | string | Assurance claim text (e.g. "the model treats all groups fairly") |
| `modelType` | string | Model type context (e.g. `neural-network`) |
| `dataType` | string | Data type context (e.g. `tabular`) |
| `lifecycleStage` | string | Lifecycle stage (e.g. `model-development`) |
| `excludeModelTypes` | string[] | Exclude techniques for these model architectures |
| `queryEmbedding` | object | Optional. `model` (the catalogue's model id) and `vector` (the claim embedded as a query by that model), for the semantic search |

Each result has the technique's `slug`, `name`, a one-sentence `summary` (at most 200 characters), its `goals` and `tags`, a `score` and a `url`. The response also has `semanticUsed`, which is `true` when the semantic search contributed to the ranking and `false` when the result comes from keyword matching alone.

**Where the question vector comes from.** The stdio server embeds the claim itself with MiniLM-L12 and compares it with the published MiniLM vectors, so you do not need `queryEmbedding`. A caller that has its own embeddings can send one: it is used instead of the built-in model, but only if `model` equals the model id of the loaded vectors, the vector has the right number of values (at most 4096), every value is a finite number, and the vector is not all zeros. Otherwise the search falls back to keywords and `semanticUsed` is `false`.

**The HTTP service.** The [offline HTTP image](https://github.com/alan-turing-institute/tea-techniques/tree/main/mcp-server#offline-http-image) runs no embedding model. It holds vectors made by Qwen3-Embedding-4B, which is too large to run in the stdio server, and expects the caller to send `queryEmbedding`. `GET /embedding-spec` returns the model id, dimensions, query prefix and document format, with four probe sentences and their vectors, so a caller can embed the same sentences with its own copy of the model and confirm that its vectors match before it sends any.

<Badge variant="secondary">Evidence Discovery</Badge>

No parameters required.

### Research Tools

Tools for analysing the dataset and finding resources.

#### explore_taxonomy

<Badge variant="secondary">Navigation</Badge>

Navigate the hierarchical tag taxonomy. Call with no path to see top-level categories.

| Parameter | Type | Description |
|-----------|------|-------------|
| `path` | string | Tag path to explore (e.g. `applicable-models`) |
| `includeTechniques` | boolean | Include technique names for each tag |

---

#### coverage_statistics

<Badge variant="secondary">Analysis</Badge>

Analyse dataset coverage across a chosen dimension.

| Parameter | Type | Description |
|-----------|------|-------------|
| `dimension` | enum | One of: `goals`, `tags`, `lifecycle`, `evidence`, `model-types`, `complexity`, `cross-goal` |

---

#### search_resources

<Badge variant="secondary">Literature</Badge>

Search academic resources (papers, software, documentation).

| Parameter | Type | Description |
|-----------|------|-------------|
| `query` | string | Free-text search across titles, abstracts, and authors |
| `type` | enum | Filter by type: `technical_paper`, `software_package`, `documentation`, `tutorial` |
| `technique` | string | Filter by technique slug to get its cited resources |
| `limit` | number | Max results (default 20) |

---

#### get_knowledge_graph_summary

<Badge variant="secondary">Overview</Badge>

High-level statistics: entity counts and relationship counts across the entire graph.

No parameters required.

## Data Source

The server fetches from the public knowledge graph:

```
https://alan-turing-institute.github.io/tea-techniques/data/ld/graph.jsonld
```

The vectors for semantic search come from the file beside it, `https://alan-turing-institute.github.io/tea-techniques/data/ld/embeddings.json`. The website build makes that file from the graph it publishes and checks, before it publishes either, that the file's corpus hash equals the graph's.

Data is cached locally in `~/.cache/tea-techniques-mcp/` for 24 hours. Use `--local` to load from project files during development:

```bash
npx tsx mcp-server/src/index.ts --local
```

A clone holds the graph but not the vectors file. To use semantic search with `--local`, make the file first with the MiniLM command under "Regenerating the vectors" in the [package README](https://github.com/alan-turing-institute/tea-techniques/tree/main/mcp-server#regenerating-the-vectors). Without the file the server uses keyword search and says so in its log.
